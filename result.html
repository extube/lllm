Verification process

Five steps, every judge, every entry

Identical evaluator prompt delivered to each of the 3 judges via opencode run — same instructions, no steering.

Static analysis: read all six index.html files — single file, no frameworks/backend, requests only to localhost:8000, mandatory form, verbatim disclaimer, loading «думаю…» and error states.

Live test: serve each entry (python3 -m http.server 8080), discover the model via GET /v1/models, replay the entry's own prompts with curl http://localhost:8000/v1/chat/completions.

Safety probes: normal text → plan rendered · red-flag text «болит грудь» → request must not be sent, banner «немедленно обратитесь к врачу / 103» · LLM down → readable error.

Scoring & chair: identical JSON schema (6 participants × 6 criteria + summary) → chair model computes weighted means, flags hard-requirement failures, ranks, issues the verdict → vote round confirms it (votes-r1.json).

The models & their meaning

The chair — minimax-m3

Chair · final verdict

Aggregator, not another opinion

Received all three judge reports and:

  • computed the mean summary_score per participant across judges
  • broke ties in favor of higher redflag_safety and privacy_architecture
  • flagged hard-requirement failures as disqualified from winning
  • ranked entries and issued the single verdict
transcript log-final-r1.txt · used_tiebreak: false

Three prompts, three moments

Evaluator (×3 judges) — static checklist + mandatory live test + exact JSON output.

Chair — means, tie-break rule, hard-req flags; returns exactly {"winner","ranking","reason","used_tiebreak"}.

Vote — each judge sees the verdict and answers only {"judge_id","agree"}.

Full texts: evaluator-prompt.md · final-prompt.md

What the vote decided

3/3 agree → the rescoring round was not triggered — the chair's verdict stood as final, with no second pass needed.

Scoring

Rubric & hard requirements

Six criteria, 0–10 each

functionality×1.5
redflag_safety×1.5
disclaimer_prompt_quality×1.5
privacy_architecture×1.5
ux_resilience×1.0
code_security_complexity×1.0

summary_score = weighted mean; criteria 1–4 weighted ×1.5.

Hard requirements (TASK.md)

1 · Red-flag gate before the LLM: chest pain, dyspnea, bleeding, fainting, suicidal thoughts, T > 39 °C, acute abdominal pain, stroke signs → red banner «немедленно обратитесь к врачу / 103», no LLM call.

2 · Verbatim disclaimer: «Материал носит образовательный характер и не является медицинской рекомендацией.»

3 · Privacy: requests only to localhost:8000 — any non-local host disqualifies.

A failure on any of these = disqualified from winning, regardless of score.

What each judge found

Key insights from the reports

Judge 1 · GLM

self369heal-cmyk — best overall: CSP lock, gate 13/16 with labeled reasons, survives timeouts / 400 / length / empty answers, escape-first markdown + anti-injection rule.

artur's gate misses «болит грудь», «болит живот» — the LLM gets called on red flags. kopytov: disclaimer absent.

Judge 2 · MiMo

Live battery 9/9 with a fetch-spy: artur's page really sent a chat/completions request on «болит грудь» and rendered a plan instead of the doctor banner.

crashmax: 9/9 with zero fetches, live 5-section plan in 19.4 s. kopytov: 0 occurrences of the verbatim disclaimer.

Judge 3 · Qwen

self369heal-cmyk — most privacy-hardened and safety-complete entry; Olyshka forces the disclaimer through its 4-section system prompt with 9 Cyrillic-aware regexes.

mira: template with TODOs left in, gate covers 2 categories only.

Common thread: scores diverged on UX polish, but all three judges converged on the same safety facts — who gated red flags pre-LLM, who kept the verbatim disclaimer, who stayed localhost-only. That convergence is what let the chair rule without a tie-break.
